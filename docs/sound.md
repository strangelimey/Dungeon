# Sound

**Status:** PLAN (Michael, 2026-08-08). Branch `sound`, worktree
`C:\Dev\Dungeon-sound`. Nothing built yet.

The reference is **Myst and Riven**. What made those worlds feel inhabited was
not the effects layer — it was the ambience: water dripping somewhere out of
sight, wind moaning down a tunnel, the sense that the room had a size. That is
the target. A dungeon that sounds like a place, not a dungeon that goes *clang*
when you hit something.

Everything else in this doc is in service of that.

## Current state

The audio layer is the thinnest system in the project, and every ambition below
is blocked on it.

- **`Audio/AudioEngine`** — 161 lines. XAudio2, a 32-voice pool, and one entry
  point: `Play(sound, volume, pan, pitch)`. **Fire-and-forget**: no handle is
  returned, so a playing sound cannot be stopped, faded, moved or looped. Mono
  sources get a constant-power pan into the stereo master. One mastering voice;
  no submixes, no effects, no 3D.
- **`Game/SoundBank`** — a flat struct of nine named `SoundData` fields. The one
  content system in the project that is *not* catalog-driven; adding a sound is
  a C++ field, a loader line and a call site.
- **`assets/sounds/*.wav`** — all nine are PROCEDURALLY SYNTHESIZED by
  `tools/AssetBaker/SoundBaker.cpp` and committed (they are tiny). Placeholders,
  and the call sites admit it: *"reuse the monster voice"*, *"a soft clunk until
  a click exists"*.
- **~30 call sites** across `DungeonWorld`, `DungeonWorld_Combat`,
  `DungeonWorld_Load`, `GameUI` and `Game`, every one a bare `m_audio.Play`.
- **One master volume slider** in Settings → Audio.
- **Doors shipped silent** — deferred out of the doors thread into this one.

## Decisions taken up front

Settled with Michael before any code (2026-08-08):

1. **Bought audio is gitignored and regenerable.** Raw downloads live in
   `OneDrive\DungeonAssets\audio\<category>\`; imported wavs land in
   `assets/sounds/` and are ignored by git, regenerated by
   `tools\FetchSounds.ps1`. Identical to how textures and bought models already
   work — and it means **worktree provisioning grows a third step**
   (see the CLAUDE.md worktree checklist).
2. **The engine is built whole, in one phase.** Voice handles, X3DAudio, submix
   buses and reverb all land together, before any content is wired. Slower to
   the first audible sound; nothing gets rebuilt afterward.
3. **Acoustics are derived from map geometry**, not authored per level, with a
   per-level override in the existing `atmosphere` record for when the
   derivation reads wrong.

## The rule that shapes the pipeline

**3D positional audio requires mono source assets.**

X3DAudio's whole job is to compute a per-channel output matrix from the geometry
between an emitter and the listener. Hand it a stereo file and there is nothing
left to place — the two channels are already committed to left and right, and it
plays as authored no matter where the party stands.

So the import path forks at the top, and the fork is a property of the *sound's
role*, not a preference:

- **Positional** — anything that belongs to a place or a body: drips, a door, a
  footstep, a sword landing, a monster's groan. **Downmixed to mono at import.**
- **Non-positional** — the level's ambient bed, UI clicks, music. **Kept
  stereo**, played straight to the master, never spatialized.

Getting this wrong is quiet rather than loud: a stereo drip simply refuses to
move as you walk past it, which reads as "the 3D isn't working" long after the
3D is working fine.

## Sourcing

**Start with the free tier, which is not a compromise.** The
[Sonniss GDC Game Audio Bundle](https://gdc.sonniss.com/) is given away yearly —
hundreds of GB of professional libraries, royalty-free for commercial use, no
attribution, no per-project limit, every past year still downloadable.

The catch is that it is **organized by vendor, not by what the sound is**. The
real cost of "free" there is the listening and sorting. For the ambience layer
specifically it may be worth skipping that: [Gravity
Sound](https://gravitysound.studio/products/cave-ambience-pack-1) sells a
27-track cave pack and a 65-track dungeon pack as seamless one-minute loops —
already the exact format a bed wants.

Paid, for filling named gaps:

- [Zapsplat](https://www.zapsplat.com/sound-effect-packs/cave-atmospheres/) —
  a Cave Atmospheres pack that reads like the brief verbatim (wind through
  tunnels, water running down cave walls, underground streams), plus
  footsteps-on-rock.
- [A Sound Effect](https://asoundeffect.com) — the fab.com of audio: a
  marketplace of independent library makers, bought per pack.

Free supplements: [Freesound](https://freesound.org) (**licence varies per
clip** — CC0 vs CC-BY has to be checked file by file, unlike the others) and
[OpenGameArt](https://opengameart.org/content/loopable-dungeon-ambience).

Every acquisition gets a `docs/costs.md` row at import time, per the standing
rule.

## Phases

### Phase 1 — Sourcing and the import path

`tools\FetchSounds.ps1` with a `$soundSets` table (the `$propSets` /
`$modelSets` idiom), plus an `AssetBaker import-sound` that resamples, trims,
normalizes, **downmixes to mono when the entry is positional**, and verifies a
loop is seamless. Raw stays pristine in OneDrive; `assets/sounds/` is the
derived tree.

### Phase 2 — The engine

The load-bearing phase. Four things, together:

- **Voice handles.** `Play` returns something addressable so a sound can be
  stopped, faded, looped, and repositioned while it plays. Everything below
  needs this; nothing today has it.
- **X3DAudio.** Listener from the camera — and it must read `Party::EyeYaw()`,
  **not** the grid facing, or the world will refuse to turn under free-look.
  Emitters carry a world position, an inner radius and a falloff.
- **Submix buses** — Ambience / SFX / UI / Music. Real category volume sliders
  fall out of this for free, replacing the lone master.
- **Reverb.** The XAudio2 reverb XAPO on a wet bus, its parameters driven from
  Phase 7's space measurement.

### Phase 3 — `sounds.cat`

Ids replace the nine struct fields, and the bank becomes a catalog like every
other content system. Per entry: the file(s), gain, pitch range, loop flag,
positional flag, falloff radius, bus.

**Variants matter more than they sound like they do.** One footstep wav played
every step is a machine gun; the fix is several takes picked round-robin with a
little pitch jitter, and it wants to be a property of the catalog entry rather
than something each call site improvises.

### Phase 4 — Ambience *(the actual goal)*

Two layers:

- **The bed** — one non-positional stereo loop per level, named in the
  `atmosphere` record beside dust/haze/ambient.
- **Emitters** — positional loops placed as **fixtures**. A dripping cell is a
  fixture with a sound, which means it arrives in the editor palette, on the
  map overlay, and in the level format with no new plumbing. This is the same
  "compose, don't bake" instinct that retired the wall `columns` knob.

### Phase 5 — Footsteps

The matrix: **footwear × surface**. A `footstep = stone` token on the floors.cat
entry, a `footstep = plate` on the boots in armor.cat, crossed at the step.
Monsters bring their own token from monsters.cat (bone, wet slap, claw). Needs a
fallback so an unauthored pair degrades to a generic step instead of silence.

Party steps fire from `Party::onStep`; monsters from their own move cadence.

### Phase 6 — Impacts

The same matrix idea: **what hit × what it hit**. A sword on a wooden shield is
not a club on plate.

This hangs off **`fx::Deal`** — already the one place every source of damage
passes through, and the only place both sides of a blow are known at once. The
attacker side is already typed (seven damage types); the defender needs a
material token on armor.cat and monsters.cat.

Because the pipeline's stages are already named and separate, three more cues
come almost free: a **swing whoosh** on a miss (strike), a **deflect** ring
(deflect), and an **absorb** cue (absorb) — each distinct from the landed blow.

### Phase 7 — Spells

A spell is not one sample. **A fireball whooshes and then explodes**, and those
are two different sounds in two different places — so the unit here is a
sequence, not an id:

- **Release** — at the caster. The cast voice that exists today, but per school.
- **Flight** — a loop that **travels with the projectile**. This is the first
  real consumer of *reposition a playing voice*, and it is why Phase 2 returns a
  handle at all. `ProjectileSystem` already assigns each shot a stable runtime
  id (the map overlay's projectile inspector uses it), so a voice keys off that
  id and dies when the shot does — no new bookkeeping.
- **Impact** — the explosion, at the point of the hit rather than at the caster.

**Wards charge rather than fire**, and they are effects, not projectiles — so
their sounds belong on **effects.cat, right beside `plume`**, which already
holds an effect's look. Three moments, the same three the visuals already have:
a **charge** on application, an optional **sustain** loop while it stands (a
burning body crackles; a ward hums), and a **break** when it is spent or times
out. Presentation stays derived — the same property that makes a burning body's
plume and light restore for free after a load restores its crackle too.

Authoring falls back rather than requiring a full matrix: an unauthored bolt
takes **its damage type's** impact sound, so a new fire spell is audible the
moment it exists and only gets its own voice if it earns one.

One judgment call to make when this lands: `spells.cat` is documented as
*numeric overrides only* — the class is the identity. Sound ids are neither
numbers nor identity but presentation, so they sit alongside `icon`/`plume` in
effects.cat comfortably and less comfortably in spells.cat. If it grates,
per-spell sounds can key off the spell id from `sounds.cat` instead, leaving
spells.cat untouched.

### Phase 8 — Derived acoustics

Measure the space around the listener from the map — an open-cell flood plus a
cardinal raycast gives both a volume and a corridor-vs-hall aspect — and drive
the reverb's decay and wet level from it, interpolated as the party moves so it
never steps. Per-level override in `atmosphere` for when it reads wrong.

Phases 4–8 are independent once 2 and 3 land.

## Traps to build against

- **The steady-state allocation rule is CHECKED.** Emitter updates, the listener
  refresh and the space measurement all run per frame, and `alloctest` will fail
  the frame if any of them allocate. Build them against pooled/flat storage from
  the start — this is much cheaper than retrofitting, as the AI snapshot work
  already demonstrated.
- **Zero-copy playback outlives the caller.** `AudioEngine` reads sample memory
  in place, so a `SoundData` must outlive its playback — the reason `~Game`
  calls `StopAll()`. Looping ambience makes this sharper: a level swap that
  frees a bed while its voice still plays is a use-after-free, not a glitch.
- **Never `CoInitializeEx` the main thread.** XAudio2 2.8+ needs no COM, and the
  audio engine's constructor used to join the main thread to the MTA — which
  silently deadlocked every shell dialog. Any new audio init keeps its hands off
  the apartment.
- **A stereo file cannot be spatialized** (see above). It is a silent failure.
- **The bought tree is gitignored**, so a fresh worktree has no audio at all and
  the game must survive that. `LoadSound` already warns and runs silent for a
  missing file; that behaviour is load-bearing now, not a nicety.
